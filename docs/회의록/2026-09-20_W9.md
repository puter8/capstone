## ml 현 상황 정리

### 1. 어떤 데이터를 모았나

| 데이터 | 양 | 용도 |
| --- | --- | --- |
| 학습용 발화 | **3,137개** | AI 모델을 훈련시키는 데 씀 |
| 검수용(dev) 발화 | 200개 | 사람이 점수 매김, 모델 성능을 재는 시험지 |
| 최종 판정용 발화 | 176개 | 아직 아무도 안 봄, 최종 합격 심사용으로 금고에 넣어둠 |

숫자만 보면 "3,137개면 충분하지 않나?" 싶은데, 진짜 문제는 여기서 나왔습니다.

### 2. 지금 문제 — 데이터 양이 아니라 "정답의 신뢰성"

**핵심 발견: 학습용 발화 3,137개 중 "사람이 검토했다"고 표시된 것들이, 실제로는 전부 AI가 만든 초안을 사람이 그냥 자동으로 승인한 것이었습니다. 진짜로 사람이 직접 점수를 매긴 건 하나도 없었습니다.**

즉:

- **3,137개 중 진짜 사람 정답 = 0개**
- 진짜 사람 정답은 검수용 200개, 그리고 아직 안 뜯어본 금고 속 176개뿐

그래서 지금 모델이 배우고 있는 "정답"은 사실 **AI가 만든 규칙 함수 하나가 매긴 점수**일 뿐입니다. 그 규칙 함수 자체가 진짜 사람 판단과 비교하면 정확도가 낮고(특히 "친밀함" 축에서), 출처마다 편향도 다릅니다.

### 3. 그래서 "데이터가 부족한가?"에 대한 답

**아닙니다.** 정확히는:

- ❌ 양이 부족한 게 아님 (3,137개는 이런 작업에 적은 수 아님)
- ✅ **믿을 수 있는(독립적인) 사람 정답이 없는 게 문제**
- ✅ 그 부족한 정답 대신 쓰던 "AI가 만든 자동 정답"의 질도 낮았던 게 문제
- ✅ 그 낮은 정답조차 모델이 제대로 못 배우고 있었던 것도 문제 (모델을 바꾸니 개선됨)

비유하면: **연습문제집은 3,137페이지나 있는데, 그 문제집의 해설지가 전부 "정답을 맞게 검증 안 한 가답안"이었던 것.** 문제집을 더 많이 사는 게 해결책이 아니라, **해설지를 진짜 선생님이 검증하는 게** 해결책입니다.

### 4. 지금 막힌 지점

그 "진짜 선생님 검증"을 소규모로 해보려고(60문장) 두 명에게 독립 채점을 부탁했는데, **두 사람 결과가 85%(51/60) 완전히 똑같이 나와서** — 진짜 독립적으로 채점한 게 맞는지 확인이 안 된 상태로 멈춰 있습니다. 이게 지금 유일하게 막힌 지점입니다.

## [BE]

### 1. `/api/usage` 스키마 수정 — 배포 동시성 필수

현재 `frontend/lib/api/schemas.ts:122` 가 `plan: z.literal("free")` 이므로, 백엔드가 Pro 사용자에게 `"pro"` 를 내려보내면 **zod 검증 실패**.

**수정 내용**

```ts
plan: z.enum(["free", "pro"]),
unlimited: z.boolean().optional(),   // 추가
```

- `remaining_turns` · `daily_limit` 은 **숫자 그대로 유지** — 나머지 스키마 변경 불필요
- 백엔드 PR(`gsd/phase-9-pro-unlimited`)과 **동시 배포 필요** — 먼저 나가면 Pro 화면 깨짐

### 2. Pro 무제한 — 백엔드 반영 완료

- 기존: 구독 무관하게 전원 일일 20턴 제한 → **Pro도 차단되던 문제 해결**
- 변경: `subscriptions.entitled` 확인 후 Pro는 한도 미적용
- 응답에 **`unlimited: true` 플래그 추가**
- `unlimited: true` 일 때 `remaining_turns` · `daily_limit` · `exhausted` 는 **의미 없는 값이므로 무시 처리**
- 사용량 카운트는 서버에 계속 기록 — **사용자 화면에는 노출 불필요**
- `UsageSummary.tsx` 의 `subscription.entitled` 분기는 **그대로 유지 가능**

### 3. 프로필 사진 해상도 — 이미 반영 완료

- Google: `s96-c` → **`s512-c` 자동 정규화**, `?sz=` 형태도 512 처리
- Kakao: `thumbnail_image_url` 대신 **`profile_image_url`(480~640px) 우선 사용**
- 프론트는 기존대로 **`avatar_url` 사용** — 추가 작업 없음
- CI 회귀 테스트 적용 완료

### 4. 결제 — 현재 미연동 상태 공유

- 결제 버튼 → `checkout` 생성은 동작하나 **가짜 URL 반환**(`mock-checkout.local`)
- **결제 후 Pro 자동 전환 안 됨** — 결제사 미연결 상태
- Pro 전환 경로는 **webhook 또는 `/api/subscription/refresh`** 두 가지뿐 — 클라이언트 영수증으로는 전환 불가(보안 설계)
- 카카오페이 키 확보 전까지 **결제 UI 비활성 또는 "준비 중" 안내 권장**
