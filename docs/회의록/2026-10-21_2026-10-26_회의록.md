## 2. BE 마이그레이션 및 PR #127

### 2.1 배경

10/15 머지된 #126에서 Pally의 누적 방식을 바꿨다.

- 기존: 발화마다 EMA(새 값 70%)를 적용해, 마지막 2~3개 발화가 Pally 모습을 거의 다 결정했다. 5턴 대화 하나를 하고 나면 그전 대화의 영향이 약 0.2%로 줄었다.
- #126 이후: **대화 하나 = 한 표.** 대화의 발화 점수를 평균내고, Pally를 그 평균 쪽으로 `α = max(1/(n+2), 0.2)`만큼 옮긴다(n = 끝낸 대화 수). 신규 사용자는 바로 변화가 보이고, 오래 쓴 사용자는 꾸준히 조금씩 닮아간다.
- 친밀도(Intimacy)는 발화 문구 대신 `app_session_started`가 기록된 KST 날짜 수로 계산한다(5일째 중간, 21일째 높음).

#126 머지 후 Codex 교차 리뷰에서 아래 3가지 P1 문제가 나왔고, #127이 이를 고쳤다.

| # | 문제 | 상황 | 영향 |
| --- | --- | --- | --- |
| 1 | 이어 하기 이중 반영 | 끝낸 대화를 History에서 다시 열면, 그 대화의 기여분이 누적에 이미 들어간 상태에서 한 번 더 반영됐다 | 같은 대화가 Pally 모습에 두 번 영향 |
| 2 | 동시 종료 덮어쓰기 | 같은 사용자의 대화 두 개가 거의 동시에 끝나면, 각자 같은 이전 상태를 읽고 결과를 써서 한쪽 반영이 사라졌다 | 대화 하나가 누락 |
| 3 | 분석 실패 시 사용량 미환불 | 5축 분석기가 실패해도 이미 예약한 턴 사용량이 차감된 채 남았다 | 사용자가 말도 못 하고 무료 턴만 소모 |

### 2.2 마이그레이션 — `supabase/migrations/20261015000000_cumulative_votes.sql`

```sql
alter table public.messages add column if not exists raw_axes jsonb;
alter table public.sessions add column if not exists axes_contribution jsonb;
```

| 컬럼 | 저장 시점 | 내용 |
| --- | --- | --- |
| `messages.raw_axes` | 사용자 턴 저장 시 | 분석기가 낸 그 발화의 원점수(누적 반영 전 5축) |
| `sessions.axes_contribution` | 대화 종료 시(종료 RPC 직전) | 그 대화의 표: `{"mean": 5축 평균 \| null, "turns": 발화 수, "first_completed_at": 처음 끝낸 시각 \| null}` |

- 컬럼 추가만 하는 forward-only 변경이다. 기존 데이터는 바꾸지 않는다.
- 두 테이블 모두 RLS가 이미 켜져 있고, 기존 행 단위 정책이 그대로 적용된다. 표는 서버(service role)만 쓴다.
- `first_completed_at`이 `null`이면 다시 연 적 없는 대화이고, `ended_at`이 곧 처음 끝낸 시각이다. 대화를 다시 열 때 `ended_at`이 지워지므로 그 값을 `first_completed_at`으로 옮겨 적는다.
- 배포 순서: **마이그레이션 먼저 → 코드 머지.** 새 코드는 두 컬럼을 읽고 쓰므로, 컬럼이 없으면 턴 저장과 종료가 실패한다.

### 2.3 코드 변경 (`backend/main.py`, `ai/matrix_engine.py`)

누적값을 "이전 상태에 덧붙이기"가 아니라 **끝낸 대화들의 표를 처음부터 다시 계산(replay)** 하는 방식으로 바꿨다. 매번 처음부터 계산하므로 같은 대화가 두 번 들어갈 수 없고, 동시에 끝난 대화끼리 서로의 결과를 덮어쓰지 않는다.

| 시점 | 동작 |
| --- | --- |
| 턴 | 이번 발화 원점수를 `raw_axes`로 저장. 이번 대화의 앞선 발화는 저장된 `raw_axes`를 쓰고, 컬럼 도입 전 발화만 다시 분석한다. 끝낸 대화들의 표 + 이번 대화의 현재 평균을 **이번 대화 자기 자리**에 넣어 다시 계산한다 |
| 턴 — 분석 실패 | 예약한 턴 사용량을 환불하고 `502 analysis_failed`를 반환한다. 메시지는 저장하지 않는다 |
| 종료 | 종료 RPC **전에** 표를 기록한다(실패하면 대화가 닫히지 않으므로 `/complete` 재시도로 복구). 닫은 뒤 마지막 턴까지 담아 표를 다시 기록하고, 프로필(`traits`, `current_axes`)을 갱신한다 |
| 종료 — 프로필 갱신 | 쓰고 나서 다시 계산해 값이 같아질 때까지 최대 3번 반복한다(동시 종료 대비). 3번 안에 같아지지 않으면 `traits_update_failed` 경고를 주고, 표는 남아 있으므로 다음 종료 때 바로잡힌다 |
| 재개(reopen) | `ended_at`을 지우기 전에 그 값을 `first_completed_at`으로 남긴다. 다시 연 대화는 원래 순서 자리에서 자기 표만 바뀐다 |
| 홈·마이페이지 | `profiles.current_axes`는 종료 시 표에서 다시 계산해 저장한 캐시다. 턴은 캐시 대신 매번 표에서 계산한다 |
| 공통 | PostgREST 1회 최대 1000행 제한을 넘는 조회를 끝까지 나눠 읽는 `_all_rows` 추가(대화·메시지·접속 기록) |

`ai/matrix_engine.py`에는 `conversation_mean()`(대화 하나의 표 = 발화 원점수 평균)과 `replay_cumulative()`(표를 처음 끝낸 순서대로 반영, 발화 없는 대화는 n에만 포함)를 추가했다.

변경 규모: 6개 파일, +410 / −129 (`backend/main.py`, `ai/matrix_engine.py`, 테스트 3개, 마이그레이션 1개)

### 2.4 backfill을 하지 않은 이유 (커밋 `050e3cf`)

처음에는 기존 대화에 표를 채워 넣는 backfill을 함께 만들었다가 뺐다. Pally는 아직 출시 전이라 실제 사용자가 없고, 기록이 있는 계정은 테스트 계정뿐이다. 표가 없는 옛 대화는 끝낸 대화 수(n)에는 들어가지만 모습은 바꾸지 않는다. 출시 전까지는 기존 사용자 마이그레이션을 계획하지 않는다.
