### BE 전달사항 — 답변 길이 수정

**원인**: `backend/main.py:729-730`에서 `finishReason == "MAX_TOKENS"`을 이미 감지하고 있지만 로그만 남기고 잘린 텍스트를 그대로 반환 중. 시스템 프롬프트의 "1-3 sentences" 지시는 느슨해서 Gemini가 가끔 길게 씀 → `maxOutputTokens: 512`에서 문장 중간에 강제로 잘림.

**요청 사항**:

1. `from ai.reply_shaping import shape_reply` import
2. `_call_gemini_chat()`가 반환한 `reply`에 바로 적용: `reply = shape_reply(reply)` — TTS 호출·저장·응답 리턴 **모두 이 shaped 버전을 써야 함** (화면엔 짧게 나오는데 TTS는 긴 원본을 읽는 불일치 방지). 적용 지점 2곳: main.py:854 직후, main.py:1481 직후
3. `_build_chat_system_prompt()`의 길이 지시를 더 구체적으로 강화 권장(현재는 모델이 잘 안 지킴). `shape_reply()`는 이 지시를 안 지켰을 때의 안전망이고, 프롬프트 강화가 1차 방어선.

   ```txt
   Keep your reply to ONE short sentence (about 10-15 words). Never write two sentences.
   ```

4. `MAX_REPLY_CHARS = 90`(`ai/reply_shaping.py`)은 ShortBubble 압축 말풍선 기준(세로 290px, 메시지당 2줄 여유)으로 역산한 값 — UI가 바뀌면 이 값도 같이 조정 필요.

### PM 전달사항

- 삭제 관련 → 회원탈퇴·데이터 삭제는 되돌릴 수 없으니까, 실행 직전에 본인 확인(재인증)을 한 번 더 해야하는데 그걸 뭘로 할지(팝업창 한번 더? 비밀번호 다시 입력? Google 재로그인?)
- 카카페 원화 → 월/연 구독을 원화로 얼마 받을지? (예: 월 ₩12,900 / 연 ₩129,000).
- @백은혜

  1. Gemini는 턴당 거의 $0
  2. 비용의 90%는 TTS(음성 합성)이고, 지금 쓰는 Journey voice가 유독 비쌈.
  3. ⚠️ 현재(Journey) 기준, 무료 유저가 20턴/일 다 쓰면 월 ~$14 비용 — 이건 Pro 구독가($9.99)보다 비싸요. 즉 헤비 무료유저 한 명이 유료 한 명보다 돈이 더 나감. 무료 tier가 이대로면 손해.
  4. 해결: TTS를 Journey → Chirp3-HD(Leda)로 바꾸면 무료유저 월 $14 → $3.6 (약 75% 절감) + 속도 3.4초 → 1.5초 (2배 빠름). 비용·속도 둘 다 이득이면서 목소리 회화체도 유지.
  5. 그래서 진짜 논점은 "20턴이 적정하냐"보다 "Journey voice를 계속 쓸거냐"임. Journey는 회화체 품질은 좋지만 Studio급($160/1M)이라 무료 유저 한 명이 20턴 다 쓰면 월 $14 — Pro 구독가($9.99)보다 비쌈(헤비 무료유저가 유료유저보다 돈 더 나감). Chirp3-HD로 바꾸면 20턴도 훨씬 여유로움.

  바뀌는 건 딱 하나, Pally 목소리 톤. 텍스트·기능·언어는 그대로.

  |  | Journey (현재) | **Chirp3-HD (Leda)** |
  | --- | --- | --- |
  | 느낌 | 표현력↑, 따뜻하고 대화체 ("친구" 느낌) | **Journey급으로 자연스럽고 회화체** (감정선 살아있음) |
  | 등급 | Studio급(프리미엄) | 구글 최신 HD |
  | 비용 | $160/1M자 | **$30/1M자 (약 1/5)** |
  | 속도 | ~3.4초 | **~1.5초 (2배 빠름)** |
  | 무료 20턴/월 원가 | ~$14/유저 | **~$3.6/유저** |

  즉 **Journey는 좋지만 10배 비싸고 느림**, **Chirp3-HD(Leda)는 회화체 품질을 거의 유지하면서 1/5 가격 + 2배 속도.** (초기에 후보였던 Neural2는 더 싸지만 감정선이 밋밋한 게 단점이었는데, Chirp3-HD는 그 단점 없이 회화체를 살림 → 실질 선택지는 **Chirp3-HD Leda로 전환** 권장.)

**이벤트 6종에 대응하는 6개 지점**에만 POST 한 번씩 넣으면 됨

| 이벤트 | 어디에 심나 (딱 한 번) |

- **구현 가능해요.** 표준 패턴이라 어렵지 않음.
- **미션 없앨 필요 없어요.** 이벤트 6개만 무조건 심으면 30개 중 열람형 task들이 자동으로 잡힘.

- 프사 관련 → `GET /api/profile` 응답에 `avatar_url` 추가함. 구글/카카오 상관없이 이거 하나 쓰면 됨 (provider 분기 백엔드에서 처리). **null이면 프사 없는 계정**(기본 이미지 띄우면 됨).
