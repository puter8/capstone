## 기준과 범위

Claire의 요청에 따라 프로젝트의 현재 디자인 시스템과 실제 서비스 코드를 기준으로 전체 Figma 화면을 구성했다. 브랜드는 라일락 퍼플 `#B7B5F2`·버터 옐로 `#F2DFA0`, 어두운 배경, Pretendard·Fraunces를 유지한다. 캐릭터는 Claire가 선택한 `pally-03-yellow-laugh.png`를 사용한다.

- 대상: Figma 파일 `4kLxDLD2LdbB5BiY2QT5qU`, `1015_새디자인` 페이지 `1283:1532`.
- 기준 문서: [new-design.md](../../new-design.md), [CSS 토큰](pally.tokens.css).
- 화면별 노드·경로·폭·프로토타입 자료: [manifest.json](../../output/figma-full-ui/manifest.json).
- 기본 화면·상태 57개는 360px, 반응형 표본 9개는 390px 7개·320px 2개다. 합계 66개 프레임이며 시트 상태도 이 수에 포함한다.
- 실제 서비스 10개 경로와 공통 오류·없는 페이지를 포함한다. `/dev/pally`는 제품 화면 범위에서 제외한다.
- 기존 `output/brand-exploration/`의 HTML 가이드·홈·레벨 선택은 초기 탐색 자료다. 전체 Figma와 화면 범위·메뉴·대화 시작 흐름이 다르며, 앱의 최신 전체 시안을 대신하지 않는다.

이번 작업은 Figma 설계와 문서화다. 실서버 조회, 앱 구현, 결제·데이터 삭제의 실제 실행, 커밋·배포는 하지 않았다.

`/onboarding?step=voice`는 별도 경로 수에 더하지 않으며 재진입 조회 중·실패를 포함한다. 알 수 없는 경로와 공통 오류 경계는 별도 공통 예외 프레임이다. 모든 API 상태 조합을 각각의 프레임으로 만들지는 않았다. 같은 레이아웃의 처리 중·차단·취소 복귀·오류 등은 화면 밖 설명에 정리했다.

## 흐름과 재사용 구성

- 하단 메뉴는 현재 앱의 **홈·피드백·업적·마이 페이지**를 따른다. 초기 탐색의 학습·도전·내 정보 라벨은 현재 전체 시안의 메뉴로 사용하지 않는다.
- 홈은 **대화 시작 버튼 → 팔리 선발화 → 사용자 마이크** 순서다. 팔리 발화·사용자 녹음·음성 처리·응답 상태와 종료 저장 상태를 구분한다.
- 대화 중 교정은 인라인으로 표시한다. 기록에서 여는 발화별 피드백은 이미 구현된 `/history/feedback` 경로를 반영한다.
- 주요 버튼·자동 상태 전환을 프로토타입으로 연결했다. 프로토타입의 시간 경과·성공 예시는 실제 서버 요청 완료를 의미하지 않는다.
- 이름 수정·기록 삭제·로그아웃·회원탈퇴, 구독 시작·해지 확인·해지 완료·결제 상세의 계정·결제 시트 8개와 홈 위 무료 한도 확인 시트 1개, 총 9개를 구성했다.
- 기존 변수·텍스트 스타일·컴포넌트를 재사용하고 노란 캐릭터, ContentCard, ListRow, MetricItem, Google, Kakao 컴포넌트 6개를 추가했다.

구독·결제는 현재 코드의 조건을 유지한다. 가격·무료체험 일수는 API 상품값이며 확정된 UI 정책값으로 새로 정의하지 않았다. 결제 성공 전용 페이지는 만들지 않았고, 승인 후 데이터 재조회에 따른 Pro 상태로 표현했다. 자동갱신 해지는 다음 청구를 중단하며 남은 이용 기간을 유지한다. 즉시 요금제 변경·자동갱신 재활성화·환불 화면은 추가하지 않았다.

## 예시 데이터와 검증 한계

가격·무료체험 일수·날짜·시간·프로필·대화·사용량 수치는 화면 배치를 위한 예시이며 화면 밖 주석에 표시했다. 실서버 값은 미확인이다. 사용자 계정·실서버 응답·실제 결제 내역을 조회한 결과가 아니다. 프로토타입은 음성 녹음, 결제, 로그아웃, 계정·기록 삭제를 실행하지 않는다. 외부 Google·Kakao 로그인 및 카카오페이 결제창 자체는 이번 Figma 화면 범위에 포함하지 않는다.

360px 상태 전체를 구성했지만 390px·320px는 대표 표본이다. 모든 화면의 모든 폭·문자 확대·보조기술 동작을 검증한 것으로 해석하지 않는다. 실제 앱 구현 후 인증·GCP 음성·DB 저장·결제 상태를 포함한 E2E 검증이 필요하다.

## 검수 결과

최종 구조 검사에서 66개 화면 안의 노드는 TEXT 709개, INSTANCE 560개, VECTOR 229개, FRAME 274개, RECTANGLE 20개로 집계됐다. Pretendard·Fraunces 불일치는 0개다. 이미지 30개는 개별 캐릭터·로그인 자산이며 전체 화면을 통째로 붙인 이미지가 아니다.

66개 화면을 담은 스크린샷 13장을 독립 검수하고, 지적 사항 관련 8장을 수정 후 다시 확인했다. 최종 검수 상태는 `resolved`이며 다음 항목을 반영했다.

- 활성 메뉴·회원탈퇴 라벨의 폭과 줄바꿈 수정.
- 390px 로그인 화면의 provider 원본 자산 반영.
- 무료 대화 한도를 홈 위 확인 시트로 변경.
- 목소리 등록 제목과 마침표 줄바꿈 수정.
- 기존 `03 · 화면 시안` 네 프레임의 최신 화면·흐름 동기화 및 실제 스크린샷 확인.
- 원본 섹션 전체 렌더에서 화면이 모두 보이는지 확인.

주요 버튼·자동 상태 전환의 실제 Figma reaction을 다시 읽어 유효하지 않은 연결 대상이 없음을 확인했다. 흐름 시작점은 로그인·대화·계정 세 개다. 이는 연결 구조 검사이며 **브라우저에서 프로토타입을 직접 클릭·스크롤·키보드로 재생한 결과가 아니다.** 해당 직접 재생 검증은 미완료다.

검수용 임시 프레임 13개는 제거했다. 실제 화면 노드·그룹·시트·구조 검사·검수 자료는 최신 [manifest.json](../../output/figma-full-ui/manifest.json)에 반영돼 있다. 이번 전체 Figma 작업에서 앱 코드·로컬 HTML·배포를 변경하지 않았다.

## 조사 근거

실제 서비스 코드의 경로·상태를 읽고 시안에 반영했다. 주요 근거는 `frontend/app/`의 해당 페이지, 프로필 다이얼로그·ProfileSummary, `frontend/lib/billing-view.ts`, `frontend/components/profile/BillingUI.tsx`다. 개별 프레임의 실제 경로와 노드는 [manifest.json](../../output/figma-full-ui/manifest.json)에 기록했다. 과거 초기 시안 검수는 [new-design.md](../../new-design.md)의 당일 이력으로 보존하고 전체 UI 검수로 소급하지 않는다.
