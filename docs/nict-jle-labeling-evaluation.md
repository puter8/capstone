## Human Review Quick Start

Start human review from:

- `data/fixtures/nict_jle_labeled_draft_600.jsonl`
- Spreadsheet-friendly copy: `data/fixtures/nict_jle_labeled_draft_600_review.csv`

Review these fields first:

- `utterance`: the original real learner utterance
- `axes`: draft 0-100 scores for Formality, Energy, Intimacy, Humor, Curiosity
- `reviewed_*`: reviewer-entered replacement scores in the CSV copy
- `style`: coarse utterance type
- `notes`: why the draft labeler made that judgment
- `sample_bucket`: sampling bucket used to keep the 600 rows diverse

For each row, the reviewer should either keep or adjust the five axis scores.
After review, change `label_status` from
`ai_draft_needs_human_review` to `human_reviewed`.

After the CSV is fully reviewed, convert it to gold JSONL:

```powershell
.\.venv\Scripts\python.exe scripts\build_human_reviewed_nict_dataset.py
```

Then rebuild the combined human-reviewed experiment dataset:

```powershell
.\.venv\Scripts\python.exe scripts\build_combined_axis_dataset.py `
  --nict data\fixtures\nict_jle_labeled_human_600.jsonl `
  --output data\fixtures\axis_dataset_combined_nict_human.jsonl
```

Recommended reviewer checks:

- Does the utterance sound usable for spoken Pally conversations?
- Are all five scores plausible on the `0-100` scale?
- Is high Formality reserved for polite spoken English, not essay-like English?
- Is Curiosity high only when the user asks, wonders, clarifies, or requests explanation?
- Is Humor kept low unless there is actual playfulness, teasing, joking, or exaggeration?
- Are learner mistakes judged as part of natural speech rather than automatically penalized?

## Sampling Criteria

The labeling sample keeps real spoken learner data while filtering rows that
are expensive to label and low signal.

Excluded:

- Low-information replies such as `O K`, `Only once`, and bare thanks
- Rows with anonymized `XXX` tokens
- Rows shorter than 3 words or longer than 35 words
- Rows with filler ratio above `0.3`
- Incomplete fragments ending in a preposition, determiner, conjunction, or filler

Balanced buckets:

- `learner_question`
- `learner_request`
- `short_reaction`
- `mistake_or_hesitation`
- `personal_statement`
- `narrative_description`

## Draft Labeling

Draft labels are generated by `scripts/draft_label_nict_jle_candidates.py`.
The script intentionally uses a separate rubric rather than calling the active
`RuleBasedAxisAnalyzer`, so later evaluation does not simply score an analyzer
against itself.

The draft labeler follows `docs/ai-labeling-guide.md`:

- Spoken conversation is the target, not academic or business writing.
- Learner mistakes, repetitions, and self-corrections are valid if they carry conversational signal.
- Humor is expected to be low for most NICT interview utterances.

## Evaluation Snapshot

Command:

```powershell
$env:PALLY_AXIS_DATASET='data\fixtures\axis_dataset_combined_nict_human.jsonl'
.\.venv\Scripts\python.exe ai\evaluate_axis_analyzers.py
Remove-Item Env:\PALLY_AXIS_DATASET
```

Combined accepted-label dataset, 938 rows:

| Analyzer | Avg MAE | Avg Spearman |
|---|---:|---:|
| rule | 12.42 | 0.41 |
| ml | 9.32 | 0.49 |
| hybrid | 9.84 | 0.52 |

Interpretation:

- ML currently wins average absolute error on the combined dataset.
- Hybrid has the best average Spearman correlation, which better matches Pally's need for visible style differentiation across turns.
- Because the 600 NICT accepted labels currently mirror the AI draft labels, do not treat this as final proof. Use it as the strongest current local signal for the next analyzer candidate.

## Current Analyzer Decision

Keep `rule` as the production-safe default until the product owner decides to
flip the runtime setting.

Keep `hybrid` as the primary default candidate for the next validated analyzer,
because it preserves rule-based style contrast while benefiting from labeled
examples. For the backend experiment/runtime handoff, use:

```powershell
$env:PALLY_AXIS_ANALYZER='hybrid'
$env:PALLY_AXIS_DATASET='data\fixtures\axis_dataset_combined_nict_human.jsonl'
```

`backend/main.py` already calls the analyzer through the adapter and applies
`shape_reply()` to Gemini replies, so the remaining backend task is configuration
rather than endpoint rewiring.
