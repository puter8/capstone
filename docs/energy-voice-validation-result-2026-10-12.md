## 파이프라인 (고정, 이번 결론으로 바뀌지 않음)

- librosa pYIN, `fmin=60, fmax=600, frame_length=1024, hop_length=160(10ms), sr=16000`
- 발화 구간 내부 프레임만 채점(패딩 제외), `voiced_flag & isfinite(f0) & f0>0` 마스크
- 유효 음성 프레임 50개(0.5s) 미만이면 `INSUFFICIENT_VOICING`로 거부
- `R_20_80_semitones = percentile(semi,80) - percentile(semi,20)`,
  `semi = 12*log2(f0/median_f0)` (클립 자체 median 기준 상대값)

## CREMA-D 검증 설계 (코덱스 교차검증, 2026-10-12)

- **표본**: 20명 화자(성별 균형 10/10), 화자당 최대 4개 (emotion, sentence)
  쌍 × LO/MD/HI 3단계 matched triplet = 210개 클립(실제: 70 triplet).
  CREMA-D 7442개 전체에서 실제 LFS media 엔드포인트로 다운로드.
- **한계(감사 후 추가)**: 210개 **전부 한 문장 "It's eleven o'clock"(IEO)**이다 —
  CREMA-D는 LO/MD/HI 강도를 이 문장에만 녹음했다. 단어 내용은 완벽히 통제되지만,
  다른 문장·자연 발화로 일반화되는지는 이 검증이 말해주지 않는다.
- **1차 근거**: 배우 의도 강도 라벨(LO/MD/HI). `summaryTable.csv`의
  `VoiceLevel`(사람 채점 강도)은 **CREMA-D 자체 `summarizeVotes.r` 소스를
  직접 읽어 확인**: 다수결로 이긴 감정 카테고리에 투표한 사람들의 응답만
  평균한 값이라 일반적인 각성도(arousal) 점수가 아님 — 1차 근거로 부적합,
  2차 보조 근거로만 사용(코덱스가 실제 R 스크립트를 읽고 확인, 내가 직접
  재확인).

## 실제 결과

**1) INSUFFICIENT_VOICING 비율 (강도별, n=70/단계, 실패를 분모에 포함)**

| 강도 | n | 실패 | 비율 |
|---|---:|---:|---:|
| LO | 70 | 34 | 48.6% |
| MD | 70 | 19 | 27.1% |
| HI | 70 | 15 | 21.4% |

7개 클립짜리 초기 관찰(LO가 유독 많이 실패)이 n=70 규모에서도 실제로,
크게 재현됨 — 낮은 의도 강도일수록 50프레임(0.5s) 음성 게이트를 통과하기
어렵다.

**2) 1차 순서 검정 — matched triplet (화자·감정·문장 동일, 70개 중 3단계
모두 통과한 27개만 사용)**

- Friedman χ²(df=2) = 1.556, p≈0.459 — **전체 비유의**
- Pairwise Wilcoxon (R20-80 semitone 중앙값 차이):
  - HI−LO: n=27, Δ=+0.040, p≈0.186
  - HI−MD: n=27, Δ=+0.180, p≈0.895
  - MD−LO: n=27, Δ=+0.660, p≈0.021 (보정 전)
- **코덱스 교정**: 3개 비교에 Holm 보정 적용 시 최소 p값도 0.063 — **보정 후
  전부 비유의**. "MD가 LO보다 측정 가능하게 높다"는 결론은 과장.

**3) 2차 보조 — Spearman R20-80 vs VoiceLevel (VoiceVote==의도 감정으로
제한한 67개, 오염 제거)**

- rho = −0.055, p≈0.656 (근사치) — 사실상 무상관, 뒷받침 없음

## 코덱스 최종 평가 요지

- LO-MD 결과는 다중비교 보정에서 못 버틴다, "saturation(고구간 포화)"
  해석도 근거 없음(HI-MD 비유의가 "같다"를 증명하는 게 아님)
- 27/70(38.6%)만 완전 triplet — 검정력 부족이 "효과 없음"을 증명하진
  않지만, 배치할 근거도 안 됨
- 2차 상관도 뒷받침 없음(거의 0)
- **화자 내 여러 triplet은 서로 독립이 아님** — 이번 검정들이 그 군집을
  보정하지 않았다는 한계도 명시(코덱스 자기지적)
- 결론: **지금 freeze, 추가 실험을 freeze의 전제조건으로 두지 말 것**

## 중요: 결측 편향 발견의 적용 범위 (과장 금지, 코덱스 지적)

LO가 HI보다 27.1%p 더 많이 게이트를 실패하는 건 **이 실험 샘플에서의 실제
발견**이고 검증 결과 문서·비활성화 근거에 남겨야 한다. 그러나 "실제 서비스의
조용한 사용자는 자주 Energy 신호를 못 받을 것이다"를 **이 실험이 증명한
프로덕션 사실인 것처럼 쓰면 안 된다** — 실제 대화에서의 빈도나 "조용함"이
원인이라는 것 자체는 이 실험이 측정하지 않았다. Energy가 완전히 비활성인
지금은 이 발견이 당장 렌더러에 영향 없음. 다만 Energy를 나중에 다시 켜거나,
같은 음성 게이트를 쓰는 다른 기능을 만들 때는 참고해야 한다.

## 미완료 연동 작업 (게이트 통과 후에도 남는 것 — 코덱스 감사 #11~#16)

ICSI 게이트는 "후보 채점기"를 검증할 뿐이다. 앱에서 Energy가 실제로 작동하려면:
1. **음성 경로**: STT 후 버려지는 오디오를 Energy 채점에 넘기기, 축 병합·저장·응답 계약 반영.
2. **지연·비용**: 턴당 중앙 3.0초 호출 — 응답과 병렬 처리 또는 응답 호출에 합치는 방식 설계,
   오디오 토큰 기준 턴/세션 비용 산정(현재 성공 호출의 usage 메타데이터를 저장 안 함).
3. **데이터 조건**: 사용자 음성을 Gemini Developer API로 보내는 것은 기존 텍스트 호출과 다른
   데이터 처리 — 결제 등급별 약관(무료 등급은 개선 목적 사용·사람 검토 허용), 고지·동의,
   보관/삭제 정책 확인 필요.
4. **누적값 설계(사용자 결정)**: `ai/matrix_engine.py`의 EMA는 코드상 α=0.7인데 주석은
   "α=0.3: 새 발화 30%, 급변 방지"라고 설명 — 어느 쪽이 의도인지 결정 필요. 또 tier 정답률은

   tier를 고정 대표값(예: 낮음 17/중간 50/높음 83)으로 넣을지, 초기값·결측 처리, 기존 텍스트
   Energy 누적값 이관 방법 결정 필요.
5. **결측 처리**: 프로토콜은 기권·오류를 허용하지만 `ai/contracts.py` AxisResult는 정수 Energy를

   조용히 대체한다. 음성 측정 실패를 텍스트 Energy나 임의 중립값으로 몰래 채우지 말 것.

   16kHz로 변환한다. 해제 전, 실제 앱 녹음으로 짧은 턴·조용하지만 표현력 있는 말·크지만 평탄한
   말·학습자 비유창성·기기 차이를 포함한 소규모 한국인 ESL 검증 게이트를 미리 정의할 것.

### 5. 평가 스크립트 `icsi_energy_evaluate.py`

- **intake**: 채점자 CSV를 `active_ids.json`과 대조 — 활성 ID마다 정확히 한 행, 누락·중복·외부 ID
  없음, enum 유효, 사용 불가 ⇒ 사유 있음·tier 빈칸, set·rubric_version·id_hash 일치. 통과한 **첫
  CSV를 채점자별로 `ratings_archive/`에 sha256과 함께 보관하고 덮어쓰기를 거부**(같은 파일 재제출은
  무시, 파일은 배타적 생성). 거부된 제출·덮어쓰기 시도도 `ledger.jsonl`에 남긴다. 보관된 원본·
  consensus·제3자 파일은 **사용할 때마다 ledger의 첫 sha256과 대조**하고 다르면 거부한다. 세트당 채점자 정확히 2명, top-up은
  최초 패널의 같은 두 명.
- **제외**: 한 명이라도 사용 불가 → 제외(조정으로 재편입 없음).
- **κ**: 선형 가중 Cohen's κ(low=0, mid=1, high=2, 가중 |i−j|/2), 두 명 모두 usable인 클립의 원래
  독립 채점으로 계산, **최초 패널에서만 ≥0.60 게이트**(실패하면 top-up·확정 모두 거부). top-up의 κ는
  참고로만 출력.
- **조정**: 불일치 worksheet(채점자 tier만, 모델 결과 없음; 이미 있으면 덮어쓰지 않음) → consensus 파일(`clip_id,tier`,
  tier = low/mid/high/unresolved, 불일치마다 정확히 한 번) → unresolved는 제3자 파일
  (`clip_id,tier,adjudicator`). 제3자가 지정되기 전(`THIRD_ADJUDICATOR = None`)에는 제3자 파일을
  거부한다. 조정 단계 코드는 모델 로그를 읽지 않는다.
- **reference 집계**: usable ≥60, 화자 ≥10, tier별 ≥20 — tier 부족이면 top-up. 3배치를 다 쓰고도
  tier가 부족하거나, 화자·usable 부족(tier top-up이 겨냥하지 않음)이면
  `STOP_INSUFFICIENT_HUMAN_EVIDENCE` — **모델 호출 전에 멈추고 reference를 확정하지 않는다**. 사람
  게이트를 모두 통과했을 때만 `status --write-final`이 `references_final.json`(`human_gates_pass:
  true`)을 한 번 쓴다(이게 있어야 추론 `run`과 `model-metrics`가 동작).
- **top-up(B2) 결정 규칙(계산만, 오디오 다운로드는 아직 미구현)**: 배치당 30개를 부족한 tier에
  최대잉여(largest-remainder)로 배분(동률: 부족분 큰 쪽, 그다음 low/mid/high). tier T의 stratum
  산출률 = (그 stratum의 사람-T reference 수) / (그 stratum의 조정 완료 usable 전체), 누적 기준, 배치
  시작 시 순위 고정 — "추가 2"의 "가장 자주 낸 stratum"을 이 비율로 정밀화. 채움은 부족분 큰
  tier부터, stratum이 바닥나면 다음 순위 stratum. seed = 20261013 + 배치 번호. 제외: 연습(calib)
  화자, 이미 쓴 모든 클립(source_record_id 및 ±0.1초 패딩 포함 시간 겹침, 배치 내부 포함), 전체
  타임라인 겹침 실패 클립. projected size = 현재 usable + 30. 화자 10% 상한은 **새 클립에만** 적용
  (이미 초과한 기존 화자는 grandfathered로 기록). 최대 3배치, 새 ID `topup{k}_NNN`(번호는 무작위
  순서라 목표 tier·stratum을 드러내지 않음). 30개를 못 채우면(화자 상한이 30개 가정이므로) 계획을
  쓰지 않고 멈춘다 → 해당 tier INSUFFICIENT_EVIDENCE. 결과는 `topup{k}_plan_PRIVATE.json`(오디오 받기 →

  low 전체), 반복·게인 ≥27/30. MISS는 모든 분모에 남는다. tier는 원문 응답에서 `parse_response`로
  다시 판정(저장된 필드나 점수를 믿지 않음). 예정 호출이 빠진 로그·같은 호출의 최종 기록 2개·다른

  기록은 거부.
- **합성 데이터 검증(실제 채점 아님)**: `icsi_energy_selftest.py --scratch <빈 폴더>` — 합성 데이터는

### 2026-10-13 통합 FAIL 후 이어서 수정·재검증

Claude 세션 중단 시점에 콘텐츠 해시 가드, WAV reference 대조, RecursionError 처리,

Codex가 검사를 갱신하고 아래 범위를 오프라인에서 확인했다.

- **블라인드 차단:** smoke의 실제 CREMA-D 6개 해시가 코드의 허용 목록과 정확히 일치.

- **음성 동일성:** 동결 기록의 calib 12개·panel 107개(제외 1개 포함), 총 119개가 실제 WAV와 일치.
  합성 WAV 변조 시 reference 확정과 추론이 거부되고, 모델 로그의 original 해시 변조도 지표 계산에서

  검사이며, 채점자가 외부에서 다른 파일을 재생하지 않았다는 사실까지 증명하지는 않는다.
- **중첩 응답:** 20,000단계 중첩 JSON을 외부 응답과 후보 텍스트 각각에 넣어 MISS 기록·원문 보존을
  확인했다. 같은 스케줄을 재개해도 이미 기록한 응답은 다시 요청하지 않는다.
- **채점 내보내기:** 잘못된 timestamp·사유뿐 아니라 null·배열·스칼라·빈 저장 문자열·알 수 없는
  clip ID가 들어간 저장 상태도 거부한다. calib/panel HTML을 재생성했고 두 페이지 모두
  Node 동작 검사 및 구문 검사를 통과했다. 실제 브라우저에서 사람 재생·채점하는 E2E는 수행하지 않았다.
- **평가 흐름:** 합성 사람 채점 → 조정 → top-up → reference 확정 → 모델 지표 계산 전체 검사 통과.
  κ·coverage·recall·반복/게인 지표는 독립 계산과 일치한다. 합성 실패 사례를 올바르게 FAIL로 판정하는
  검사도 포함한다. 테스트 전후 실제 패널 폴더의 모든 파일을 SHA-256으로 비교해 변경 없음을 확인했다.

재현 명령: `.venv/Scripts/python.exe .context/energy-audio-test/icsi_energy_selftest.py --scratch <새 빈 폴더>`.
최종 실행 기록: `.context/energy-audit-resume-04.log`.

**범위:** 이번 실행에는 Gemini 실호출이나 실제 ICSI 표현력 채점이 없다. 기존 CREMA-D smoke 기록은
그대로 보존했다. 실제 상태는 `WAITING_PANEL_RATINGS`(접수된 사람 원본 0개)다.
사람 채점·제3 판정자 지정, 필요 시 top-up 오디오 확보, 이후 실제 모델 평가가 남아 있다.
따라서 이 수정으로 통합 검증 전체 또는 Energy 성능을 PASS로 바꾸지 않는다.
`docs/plan/2026-10-12-five-axis-remap-proposal.md` §6.5의 움직임 활성화 조건도 유지한다.

### 통과 기준 — 변경 없음

usable ≥60, 화자 ≥10, tier별 사람 reference ≥20, 최초 패널 κ≥0.60, coverage ≥95%·tier별 ≥90%,
tier별 recall ≥60%, macro recall ≥70%, 사람-low→모델-high ≤10%, 반복·게인 tier 일치 각각 ≥90%
(=27/30). 바뀐 것은 모델 출력 방식(직접 tier)과 결정 규칙의 명문화뿐이다.
