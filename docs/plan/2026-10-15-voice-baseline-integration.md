# 목소리 등록 온보딩 연결

- 요청: 최신 백엔드 머지 pull → Figma 프론트 반영 → 목소리 등록 연결.
- 기반: `1015-frontend`에서 `origin/main`의 `af778d9`(PR #125)까지 fast-forward. 기존 미커밋 변경을 보존했다.
- 디자인: [Design_v1](https://www.figma.com/design/4kLxDLD2LdbB5BiY2QT5qU?node-id=659-1172). 안내 `1267:682`, 녹음 `1268:687/736/781/831/882/930`, 완료 `1267:725`.
- 서버 질문·길이 제한을 그대로 사용한다. 안내 → 문항 3개 → 등록 요청 → 완료로 연결한다.
- `required` 사용자는 온보딩과 홈 진입에서 등록 화면으로 이동한다. `ready`/`disabled`는 등록을 건너뛴다. 진행 중 대화 ID는 보존한다.
- 재녹음은 해당 문항만 교체한다. 서버 오류의 1-based `clip_index`를 이용하고 나머지 녹음은 유지한다. 네트워크 재시도는 같은 요청 키를 사용하며 녹음 교체 후 키를 갱신한다.
- 현재 백엔드는 이미 등록된 기준을 덮어쓰지 않는다. 별도의 재등록 기능은 이번 범위에 포함하지 않았다.
- Claire 결정: 현재 로그인 계정에서 직접 3문항을 녹음하여 실제 저장을 검증한다. 합성 음성을 실제 계정에 저장하지 않는다.
- Claire 정정: 녹음 화면 아래의 이전 문항 다시 녹음하기 문구를 제거한다. 문항 번호와 완료 목록에서 선택하는 재녹음은 유지한다.

## 검증 상태

- 실제 Railway GET `/api/energy/baseline`: HTTP 200, 594ms, `required`, 질문 3개, 길이 5~30초.
- 타입 검사, API 계약·오류 세부정보·multipart 전달, 온보딩 재저장, 오류 한국어 처리 검사 통과.
- WAV 30초 경계·PCM 헤더·모노 변환·기존 호출 호환·리소스 정리 및 mock API 계약 검사 통과.
- lint 오류 없음. 기존 및 이번 SVG `<img>` 사용에 대한 Next.js 권고 경고가 있다.
- Aside에서 안내·녹음 대기·실제 3번 녹음 중·완료 화면, 원본 SVG 로드·치수, 저장 전 버튼 비활성 상태 확인.
- 360px 실제 viewport: Aside가 viewport 설정 API를 제공하지 않아 미완료. 현재 렌더는 너비 402px 앱 컨테이너다.
- Claire가 직접 3문항 녹음·등록 후 홈에 도착한 것을 확인했다. 실제 API 재조회는 HTTP 200 / `ready` / `valid_clips:3` / `method_version:pitch-range-fold-v1`을 반환했다.
- Railway 런타임 로그에서 `POST /api/energy/baseline` 200 및 저장 후 GET 200을 확인했다. 완료 화면으로 재진입해 등록 단계가 생략되는 것도 확인했다.
- 최초 짧은 녹음 안내 후 실제 1→2→3번 진행과 등록 성공을 확인했다. 첫 시도들의 녹음 시간은 수집하지 않아 반복 안내 원인은 확정하지 않았다.
- 커밋·PR·배포 및 환경변수 변경 없음. 기존 개발 서버를 사용한다.
