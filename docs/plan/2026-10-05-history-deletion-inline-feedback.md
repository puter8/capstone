# 대화 기록 삭제 및 대화 중 피드백 연결

기준: 2026-10-05 KST, main `6ad5360` 위 로컬 변경.

> 이 문서는 10월 5일 작업 당시의 기록이다. 10월 6일 Claire가 실제 opener 연결과 커밋·푸시까지 승인했다. 피드백 생성 시점도 대화 종료 후로 바뀌었다. 아래 범위·미검증·커밋 보류 항목의 최신 상태는 [10월 6일 통합 검증 기록](2026-10-06-frontend-opener-feedback-integration.md)을 따른다.

## 요청과 구현

- Claire가 데이터 삭제 연결과 대화 중 피드백 표시(이전 정리의 1·3번)를 승인했다. Opener는 이번 변경 범위에 포함하지 않는다.
- 마이페이지에서 복구 불가·삭제 범위를 안내하고 확인 후 `DELETE /api/conversations`를 호출한다. 확인창을 연 계정과 요청 시점 계정이 다르면 요청을 차단한다.
- 처리 중 중복 요청을 막고, 성공 시 사용자 경로 캐시 및 진행 중 대화 ID를 비운 뒤 프로필을 다시 읽는다. 프로필 재조회 실패는 삭제 실패와 구분한다. 사용량·구독을 초기화하는 API는 호출하지 않는다.
- 새 응답과 복원한 대화의 각 Pally 메시지에 교정 항목·생성 실패 상태를 보관한다. 짧은 말풍선과 전체 대화에서 기존 InlineFeedbackPanel로 원문·교정문·한국어 설명을 표시한다.
- 교정이 없는 발화는 패널을 숨기고, 생성 실패는 별도 안내한다. 설명을 펼치면 스크롤 영역 안으로 이동한다. 전체 대화를 펼친 동안 캐릭터와 마이크를 숨겨 겹침을 방지한다.

## 검증

- 실제 Railway health 및 OpenAPI 조회: 삭제 경로 등록 확인. 로그인된 실제 대화 목록·상세 조회 HTTP 200, feedback 응답 필드 확인.
- `tsc --noEmit`, `npm run build`, `npm run lint` 통과. 전체 lint에는 기존 이미지 관련 경고가 있으며 변경 화면 대상 lint에는 경고·오류가 없다.
- `check:mock-api`, `check:conversation-order`, `check:query-cache`, `tsx scripts/check-billing-account-binding.ts` 통과. 삭제 후 사용량·구독·계정 설정 보존, 빈 기록 재삭제, 계정 전환 시 네트워크 요청 차단, 복원 피드백의 발화 연결을 확인했다.
- Aside 전용 탭, 별도 localhost:3001 미리보기에서 콘텐츠 폭 360px로 화면 확인. 브라우저 viewport 에뮬레이션은 도구에서 지원되지 않아 콘텐츠 폭으로 검사했다.
- 삭제는 브라우저에서 DELETE를 모의 응답으로 차단해 취소(요청 0회), 대기 중 버튼 잠금, 실패·재시도·성공, 프로필 재조회, 기록 ID 정리, 빈 히스토리와 기본 홈을 확인했다. 실제 사용자 기록은 삭제하지 않았다.
- 실제 저장 피드백을 읽어 복원 화면에 표시했다. 이 과정의 대화 활성 상태와 추가 실패·무교정 사례는 브라우저 fixture로 구성했다. 접기·펼치기, 키보드로 설명 펼치기와 스크롤, 발화별 패널, 생성 실패 안내, 공통 로그아웃·사용량 확인창을 검사했다.

## 남은 검증

- 실제 전체 삭제 성공 및 새 음성의 GCP → DB → UI E2E는 수행하지 않았다. 기존 사용자 기록을 지우거나 테스트 발화로 바꾸지 않도록, 이 검증에는 삭제 가능한 테스트 계정과 대상 확인이 필요하다.
- 따라서 구현·정적 검사·모의 브라우저 검증 완료와 실제 서비스 E2E 완료를 구분한다. 커밋·배포는 하지 않는다.
- 검증 후 localhost:3001 임시 서버를 종료하고 Aside 전용 탭·모의 응답·임시 로그인 상태를 정리했다. 기존 3000번 서버와 `.env.local`은 변경하지 않았다.
