## 2. Part B — CHARACTER MATRIX 5축 개선 (세션의 핵심)

### 2.1 배경

Pally 파이프라인: 사용자 발화 → 5축 점수(Formality/Energy/Intimacy/Humor/Curiosity, 0-100) → `ai/matrix_engine.py::compute_character()`(가중 행렬 변환) → 캐릭터 파라미터 3개(`tone_casual`/`energy_level`/`humor_level`) → (a) `ai/opener.py::persona_prompt()`(LLM 대화 프롬프트에 반영), (b) `frontend/components/pally/PallyCanvas.tsx`(3단계 `tier()`: 0-33/34-66/67-100으로 모양·색·움직임 변화)에 쓰임.

### 2.2 사용자가 세션 초반에 정한 우선순위

① Intimacy(쉬움, 비-ML) → ② F/H/C 능동학습(사람 라벨 더 필요한 3축) → ③ Energy(음성 피치/억양 분산, 가장 무거움, 그린필드 — 오디오 파이프라인이 전혀 없음).

### 2.3 ① Intimacy — 완료

- `ai/intimacy.py`(신규): `compute_intimacy_from_session_count(session_count)` — 포화 곡선 `100 × count / (count + 10)`, 5점 단위 라운딩. 텍스트가 아니라 **누적 로그인/세션 횟수** 기반(최근 활동 아님).
- `backend/main.py`: `_app_open_count()` 헬퍼(사용자의 `sessions` 행 개수 카운트) 추가. Intimacy는 `apply_ema()` **이후**에 `smoothed["Intimacy"]`를 덮어쓰도록 연결됨(1783-1788행 실측 확인):
  ```python
  smoothed = apply_ema(current_axes, raw_axes) if current_axes else raw_axes
  if ...:
      smoothed = {**smoothed, "Intimacy": compute_intimacy_from_session_count(_app_open_count(sb, user_id))}
  ```
  EMA 이전에 덮어썼다면 텍스트 기반 과거값과 섞여버리는 실제 버그였고, 코덱스가 지적해 사용자/어시스턴트가 "EMA 이후" 순서로 고쳤다.
- 카운트 조회 실패 시 조용히 폴백하지 않고 503으로 명시적으로 실패시킴(프로젝트의 "에러 삼키지 않는다" 원칙).
- 문서화: `docs/AI_TACTIC/Pally_RUBRIC_v3.0_md` §2.

### 2.4 "캐릭터가 체감상 달라지지 않는다" 진단 — 두 번의 자가 정정 후 진짜 원인 발견

1. **오진 1(정정됨)**: 프론트의 3단계 시각 밴딩(`PallyCanvas.tsx::tier()`) 자체가 문제라고 봤으나, 사용자가 PM의 원본 Figma 설계 이미지를 제시해 3단계 구조가 의도된 설계임을 확인 — 버그 아님.
2. **오진 2(정정됨)**: "프론트가 대화 중간에 캐릭터를 갱신하지 않는다"를 버그로 적었으나, 사용자가 이는 합의된 의도 동작(`frontend/lib/hooks/usePally.ts`의 `pendingAxes`/`revealAxes()`로 대화가 끝날 때까지 캐릭터를 시각적으로 고정)이라고 정정.
3. **실제 원인**: 200개 골드 라벨 세트(`ml_transition_gold_human_200.jsonl`)로 코덱스 검증 측정 — F/H/C를 완벽한 사람 골드 라벨로 바꿔도 `energy_level`은 200개 중 200개가 중간 티어에, `humor_level`은 200개 중 198개가 중간 티어에 머물렀다. 즉 F/H/C 분류기 품질과 무관하게 **가중합 행렬(`compute_character()`) 자체가 Energy/Humor의 변화를 구조적으로 억누르고 있었다**. 이 발견이 세션 나머지의 "출력 연결(matrix engine)" 작업을 촉발했다.

### 2.5 Figma 참고 페이지 재구성 (부수 작업)

현재 코드의 5축→시각 매핑을 반영한 Figma 참고 페이지를 `use_figma` MCP 도구로 갱신(백그라운드 에이전트가 격리 워크트리에서 MCP 미제공으로 실패한 후 메인 세션에서 직접 수행). 이 과정에서 나온 "렌더링을 연속으로 바꿀지 3단계로 유지할지" 질문은 사용자 지시에 따라 PM 결정 대기로 분리해 `docs/plan/2026-10-06-character-rendering-continuous-vs-tier-PARKED.md`에 보류 기록. **5축 학습 작업이 끝난 뒤 다시 논의**한다는 조건이 문서에 명시돼 있다.

### 2.6 ② F/H/C 능동학습 라운드

- `scripts/select_purpose_v3_active_candidates.py`(신규): AMI(98,475 발화)·ICSI(111,179 발화) 회의록 코퍼스의 미사용 풀에서, 기존 seed 분류기와 `RuleBasedAxisAnalyzer`의 불일치를 능동학습 신호로 써서 후보를 선정. 코덱스 리뷰로 잡은 핵심 버그: held-out 평가 파티션(31개)은 모델 기반 후보 선정 **이전에** 회의 그룹 단위로 먼저 분리해야 함(안 그러면 리키지).
- 실제 데이터 희소성 문제: AMI+ICSI 합쳐도 고유 회의가 214개뿐이고, 이전 트랙이 대부분을 이미 건드려서 첫 선정에서 150개 중 61개만 채워짐. 제외 범위를 "이전 트랙의 실제 held-out 평가 풀만" 제외(학습 풀은 제외 안 함)로 좁히고, 그룹당 상한을 1→2로 올려서 두 번째 실행에서 학습 150/150 + 평가 31/40을 채움.
- 라벨링 방식을 4인에서 1인으로 전환(사용자 결정: "논문 작성하는게 아니니까").
- 먼저 Claude Artifact 라벨링 도구(DB capability 포함 웹 UI)를 만들었으나, 존재하지 않는 API(`db.set()`/`db.list()`)를 호출하는 실제 버그가 있어 저장이 조용히 전부 실패했다. 사용자가 "저장 실패"를 보고한 뒤 원인(`db.collection(path).doc(id).set()` 등 실제 계약과 다름)을 찾아 고치고, 이미 시도했다가 날아갔던 40개 라벨을 복구했다. 이후 사용자가 Artifact 대신 **엑셀 파일로 전환**을 요청(Artifact와 씨름하는 것보다 엑셀이 더 쉬웠다는 판단)해, Artifact는 삭제하고 영어+한국어 번역, 데이터 검증 드롭다운, 이미 라벨링된 36~40행을 미리 채운 `data/fixtures/pally_purpose_v3_labeling_workbook.xlsx`가 최종 결과물이 됐다.
- "사람 라벨링 없이" 할 수 있는지(Word2Vec류 비지도 방법, 사용자가 공유한 무관한 NLP 과제 자료에서 아이디어를 얻음)도 검토하고 코덱스로 검증을 요청했다. 결론(코덱스 검증): 아니다 — 비지도 단어 co-occurrence는 Pally의 주관적 0-100 루브릭 척도를 근거로 삼을 수 없음. 군집 기반 라벨 복사는 명시적으로 기각(독립적 사람 판단이 아닌 weak-label 전파이고, 프로젝트가 이미 금지한 부트스트래핑 위험을 재도입함). 임베딩을 모델 입력 특징으로 쓰는 것(Sentence-BERT + Ridge)은 정당하지만 아직 검증 안 된 미래 레버로, 31개 평가 파티션은 절대 건드리지 않는 범위에서 나중에 별도 dev-only 실험으로 테스트하기로 함.

### 2.8 Matrix Engine 재설계 — 이번 세션 최대 작업

1. **출발점**: `compute_character()`는 3×5 가중치 행렬(`W`) + bias로 5축을 3개 파라미터로 변환하면서 여러 축을 섞었다(예: Intimacy와 Humor가 둘 다 `energy_level`에 기여).
2. **단계적 수정**:
   - 먼저 `energy_level`만 Energy가 "주도"하도록 가중치를 조정하면서 Energy가 낮고 Intimacy가 높은 입력도 "차분함"으로 렌더링되도록 요청받음. 중간 수정: `W` 행 `[0.01,0.65,0.03,0.03,0.02]`, BIAS 17(기존 `[0.05,0.40,0.15,0.10,0.10]`, BIAS 20에서 변경) — 이는 원래 가중치가 Energy=0에서도 `energy_level` 최솟값이 40으로 "차분" 임계값 34를 이미 넘어버려 절대 "차분" 밴드에 도달할 수 없었던 원래 문제를 해결함.
   - 이 중간 수정을 검증하던 중, 더 큰 문제를 발견: `PallyCanvas.tsx::tier()`(화면 렌더링)는 **원본 축 값을 그대로** 쓰고, `persona_prompt()`(LLM 프롬프트)는 **가중합 결과**를 쓰고 있어서 화면과 대화가 서로 다른 인상을 줄 수 있었다(예: 화면은 "차분한" 모양인데 AI는 "활발하게" 행동하라고 지시받음). 0-100 × 다른 4축 {0,50,100} 전수(8,181개 조합) 그리드로 측정: 중간 수정 상태에서도 화면-프롬프트 불일치가 18.2%.
   - 사용자가 `codex exec`로 독립 검증을 요청 — 코덱스가 실제 GitHub `main` 브랜치 기준으로 이 이중 경로 문제가 실재함을 확인했고, 당시까지 고치지 않은 Formality·Humor에도 동일한 구조적 문제가 있음을 추가로 발견. 다만 코덱스의 비교표는 "BIAS만 낮추고 섞는 건 유지"하는 더 약한 수정안을 기준으로 했는데, 이는 사용자 팀이 이미 넘어간 단계였다(코덱스가 보던 `main`은 작업 중인 브랜치가 아니라 오래된 상태였음).
   - **최종 결정(사용자)**: 세 출력 모두 자기 축의 완전히 독립적인 통과값으로 만들고 가중합 혼합을 폐기:
     ```
     tone_casual  = 100 - Formality   (W 행 [-1,0,0,0,0], BIAS 100)
     energy_level = Energy             (W 행 [0,1,0,0,0],  BIAS 0)
     humor_level  = Humor              (W 행 [0,0,0,1,0],  BIAS 0)
     ```
     Intimacy/Curiosity는 원래부터 행렬을 거치지 않고 `persona_prompt()`에 raw 값으로 직접 들어가서 영향받지 않았다. `apply_ema()`(alpha=0.7)와 `backend/main.py`의 "EMA → Intimacy 세션카운트 덮어쓰기 → `compute_character()`" 순서(§2.3)는 그대로 유지했다.
   - **구현 위치**: `ai/matrix_engine.py` — **아직 git에 커밋되지 않은 워킹트리 변경 상태**(`git status`에서 `M ai/matrix_engine.py`로 확인됨, 2026-10-06 기준). 신규 테스트 `tests/test_matrix_engine.py`(6개 테스트, `PYTHONPATH=.` 필요 — `ai`가 제대로 경로 설정된 패키지가 아니라서 코덱스 첫 실행이 `ModuleNotFoundError: ai`로 실패했던 것을 세션 중 발견) 작성·통과 확인. 각 출력이 정확히 자기 축과 같음(또는 `100 - Formality`)과, 화면 티어와 프롬프트 밴드가 전 그리드에서 결코 불일치하지 않음을 전수(8,181개 조합×3축) 검증한다.
   - **원래(세션 시작 전) 가중치의 불일치율 측정**(고친 버그의 크기를 문서화하기 위함): Formality 41.4%(3,390/8,181 — 전 구간에서 상시 발생, bias 50이 가중치 -0.45보다 커서 Formality 단독으로는 중립 구간을 못 벗어남), Humor 35.2%(2,877/8,181), Energy 47.1%(3,854/8,181). **주의**: 세션 초안에 Energy 원래 불일치율을 18.2%로 잘못 쓴 적이 있었는데, 18.2%는 중간(Energy만 조정한) 수정안의 불일치율이고 원래 가중치의 값이 아니다 — 이 혼동은 발견되어 정정됐다.
3. **작업 중 독립적으로 발견한 사실**: `backend/main.py`의 `/api/stt`와 턴 단위 `_stt_from_bytes`는 원본 오디오 바이트를 Google STT에 보내고 버린다 — Supabase storage 업로드도, 원본 오디오 저장도 코드베이스 어디에도 없다. 이는 아래 Energy 피치 시제품의 착수 시점 결정에 영향을 준다.

사용자가 두 개의 참고 PDF를 세션에 인라인으로 공유(로컬 파일로 저장되지 않음, 전체 텍스트를 추출해 읽음):

1. **`Pally_v3.1_강의연계_확장근거와_실행계획.pdf`**: 프로젝트 선택을 사용자의 AI/NLP 수업 자료(D01-D12, 강의개념→프로젝트적용→선택이유→한계→출처) + 외부 확장 근거(E1-E6: Sentence-BERT, scikit-learn Ridge, Settles의 능동학습 서베이, GroupKFold, librosa pyin, Praat 피치 분석 가이드)로 뒷받침하는 문서. 이 PDF는 스스로를 "부속 근거 문서"로 규정하며, 자신이 근거를 대는 대상인 "v3.1 통합 문서"가 저장소에 아직 없다고 명시했다.
2. **`Pally_5축_선행연구와_유사프로젝트_검토.pdf`**: 12편 논문(R01-R12) 문헌 리뷰 + 공개 구현 서베이. Pally의 설계가 선행연구와 **어디서 다른지**를 찾는 데 명시적으로 초점을 맞춤 (단순 확인용 인용 모음이 아님). 예: Formality는 특정 논문에서 직접 가져온 것이 아니라 프로젝트 고유 복합 척도; Humor 연구는 "웃긴가"와 "얼마나 웃긴가"를 구분하지만 Pally는 그 구분이 필요 없음; Curiosity 관련 연구(INQUISITIVE)는 단일 발화 의도가 아니라 독자가 문서에 대해 갖는 질문을 측정해 구조적으로 다름; Energy의 GeMAPS/eGeMAPS 음향 특징 표준은 Pally에게 0-100 척도나 calm/upbeat 임계값을 주지 않음(둘 다 Pally 자체 설계); Intimacy의 세션횟수 공식은 인용된 관계형성 에이전트 연구(Bickmore & Picard)가 증명하는 게 아니라 "제품 설계 값"임을 명시; 1인 라벨링(4인에서 전환)에는 Davani et al.의 평가자 불일치 연구가 지적하는 실제 한계가 있음(플래그만, 변경 없음); Best-Worst-Scaling·SetFit은 비교 후보로만 언급; 회귀 특화 능동학습(Wu et al.의 greedy sampling)이 일반 분류-엔트로피 방법보다 이론적으로 더 적합하다고 언급(다음 라운드용).

**어시스턴트가 `docs/AI_TACTIC/Pally_RUBRIC_v3.1_md`를 작성**해 두 PDF를 하나의 통합 운영 문서로 합쳤다 — 첫 PDF가 말한 "아직 없는 v3.1 통합 문서"가 이 파일이다. 구성: §0 문서 계보, §1 불변 사항, §2 근거 등급 읽는 법(직접 증거/응용 추론/미검증), §3 출력 연결 수정과 그 검증(최대 섹션), §4-§12 = D01-D11 각각(강의개념/프로젝트적용/선택이유/한계/출처/실행기준), §13 실행 일정, §14 실제 라벨링 진행 수치, §15 결정 로그 템플릿 + 첫 실제 항목, §16-17 강의/외부 출처 표, §18 마무리 요약, §19 두 번째 PDF의 R01-R12 내용, §20 최종 종합 결론.

### 3.1 1차 코덱스 교차검증 (§19-20 작성 전 단계에 수행)

실제 오류 5건을 찾아 수정:

### 3.3 Energy 피치 시제품 착수 시점 — 코덱스 권고 및 최종 결정

코덱스에 질의한 전제: 1인 개발자가 라벨링과 오디오 특징 작업을 동시에 맡고 별도 시간 예산이 없음; `librosa`는 `requirements.txt`·`backend/requirements.txt` 어디에도 없고 현재 venv에도 설치돼 있지 않음; `ai/`에 피치 추출 코드가 전혀 없음; 원본 오디오가 어디에도 저장되지 않아 시제품은 언제 시작하든 별도 테스트 녹음 수집부터 시작해야 함; 마감(10/30)까지 24일; 라벨링 150개 중 114개 남음.

**코덱스 권고**: v3.0이 원래 계획한 **3주차(10/19-25)로 연기**. 이유: (1) 1인 개발자에게 "병행"은 실제로는 우선순위가 더 높은 ②(F/H/C)의 시간을 ③(Energy)으로 돌리는 것; (2) Energy를 당겨야 했던 원래 급박함의 근거("F/H/C를 고쳐도 옛 가중합 행렬 때문에 Energy 텍스트 출력이 안 바뀐다")는 Part B의 행렬 재설계로 이미 해결됨, 그 논거가 더 이상 성립하지 않음; (3) 음향 파이프라인이 완전 그린필드(의존성 미설치, 코드 없음, 저장된 오디오 없음)라 "지금" 시작해도 "3주차"에 시작하는 것과 똑같이 테스트 녹음 수집이라는 선행 작업이 필요해서 실질적 시간 절약이 없음. 재검토 조건: 라벨링이 예상보다 빨리 끝나거나, 두 번째 인력이 합류하거나, F/H/C 일정을 늦추지 않고 비교 녹음이 준비되는 경우.

**사용자/어시스턴트가 이 권고를 최종 결정으로 채택**: Energy 피치 시제품은 3주차(10/19-25)로 연기. `Pally_RUBRIC_v3.1_md` §11·§20(§20의 2번 항목에 전체 근거와 재검토 조건 수록)에 반영했고, §13 일정표와 "이번에 바로 할 것" 문구도 이에 맞춰 "114개 남은 라벨링 완료 + `language_form` 누락 9개 보완에만 집중, 3주차까지"로 갱신했다.
