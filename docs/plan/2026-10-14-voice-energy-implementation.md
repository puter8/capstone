# 개인 기준 억양 변화량 Energy 구현 계획

2026-10-14 사용자 요청: 측정 결과를 바탕으로 에너지 축 구현·검증, 이후 5축 신뢰도 정리. 기존 사용자도 최초 1회 별도 녹음 3개로 기준값을 등록한다는 답변을 받았다.

## 확정 범위

- 세션 종료 후 외형 공개 정책 유지. 이번 작업은 측정·저장·점수 전달이며 5축 디자인 재매핑은 포함하지 않는다.
- Energy의 조작적 정의는 **개인 평소 억양 폭 대비 세션 억양 폭 변화**다. 감정·활력의 정답을 측정한다고 표현하지 않는다.
- 16kHz mono PCM16 WAV를 기존 브라우저 변환으로 전송한다. 서버 의존성 librosa 1.0.0 추가를 사전 안내했다. 별도 ffmpeg 도입은 불필요하다.
- pYIN 60–600Hz, frame 1024, hop 160. 유성 프레임 50개 미만은 결측. 각 클립 중앙 F0 대비 반음으로 변환하고 ±7반음 밖 프레임을 한 옥타브 접는 휴리스틱 후 P80−P20을 구한다. 실제 큰 억양도 접을 수 있으므로 ‘옥타브 오류가 확정되어 교정됨’이라고 설명하지 않는다.
- 개인 기준: 유효 녹음 3개의 억양 폭 중앙값. 세션: 기준 녹음과 분리된 유효 발화 최소 5개의 중앙값. 최소 5개는 첨부 시뮬레이션 조건을 따른 보수적인 구현 기준이며 일반화 검증된 최적값은 아니다.
- 점수: clip(50 + 10 × Δ, 0,100), 5점 단위 반올림. 반올림 후 33/66 경계를 적용하면 정확한 Δ 경계는 ±1.7이 아니다. 경계는 계산 코드로 검증한다.
- ‘두 세션 같은 단계일 때만 외형 변경’은 디자인 안정화 제안이다. 측정 점수와 섞지 않고 이후 5축 매핑 논의로 남긴다.

## 구현 순서

1. 실제 녹음 10개 수치·해시·실행시간 재현, 무음/손상/길이/경계 검증.
2. 순수 측정 함수와 기준값·세션 집계 구현. 수치 부족·측정 실패를 0점이나 텍스트 점수로 대체하지 않는다.
3. 인증된 3클립 기준 등록 API/UI, 사용자별 기준 저장. 서버 플래그 비활성 상태와 미등록 상태를 구분한다.
4. 메시지와 함께 작업 입력을 영속 저장, 별도 worker가 순차 측정. 처리 후 원음 입력 제거. 세션 종료는 점수 스냅샷을 원자적으로 확정한다.
5. 종료 시 미완료 작업·유효 발화 부족은 직전 음성 Energy(없으면 명시적인 중립 초기값 50)를 유지하고 사유를 반환한다. 늦은 작업이 이미 공개한 값을 다시 바꾸지 않는다.
6. 종료 응답·히스토리·다음 대화·성향 태그가 같은 스냅샷을 사용하게 연결한다.
7. 계산/작업복구/반복 종료/재개/권한 경계 테스트, 프론트 타입·브라우저 확인, 실제 서비스 E2E 범위를 별도로 보고한다.

## 신뢰도 및 속도 해석

첨부 자료는 한 사람·10클립이다. 88% 중간 비율은 동일 자료 재조합 안정성 지표이며 정확도가 아니다. 대조 조건의 민감도나 다수 사용자 일반화는 검증되지 않았다. 측정 가능성과 사람 판단 일치도를 분리한다.

동일 서버 백그라운드 실행도 CPU/메모리를 사용한다. 턴 응답이 측정을 기다리지 않게 하고 처리 동시성을 제한하지만 응답속도 ‘영향 없음’ 또는 종료 처리 ‘0초’를 보장하지 않는다. 재시작·다중 인스턴스를 위해 영속 작업과 조건부 저장이 필요하다. [FastAPI 공식 Background Tasks 안내](https://fastapi.tiangolo.com/tutorial/background-tasks/)도 무거운 작업의 별도 처리 도구를 설명한다. 측정 API는 [librosa 공식 pYIN 문서](https://librosa.org/doc/main/generated/librosa.pyin.html)를 기준으로 한다.
