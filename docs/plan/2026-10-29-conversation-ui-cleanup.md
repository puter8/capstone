# 대화와 피드백 화면 정리

## 결정 · 2026-10-29 KST

- ‘새 표현’은 화면 안내·색상·밑줄뿐 아니라 Gemini의 별도 생성 지시와 분류까지 제거한다.
- ‘오늘의 표현’은 유지한다. 하루 표현 선발화와 업적 기능은 이번 제거 대상에 포함하지 않는다.
- 음성 정보 부족·분석 미완료로 Energy를 유지했다는 안내는 화면에 표시하지 않는다. Energy 계산과 API 진단 정보는 보존한다.
- 피드백 목록 카드에서 Pally 캐릭터, 대화 미리보기, ‘N번 주고받음’을 제거한다. 피드백 상세의 동일 턴 수 표시도 제거한다.
- 카드에는 시간·제목·고친 표현 개수·이어서 대화를 남긴다. 제목이 없을 때 미리보기를 대신 보여주지 않는다.
- 기존 대화 본문·교정·저장 데이터는 삭제하지 않는다.

기존 디자인 문서의 ‘새 표현’ 강조 규칙보다 이 결정을 우선한다.

## 구현

- Gemini 내부 응답 계약은 6개 필드다. `new_expr`를 요청하거나 응답 조각으로 생성하지 않으며, `own_remark`는 일반 문장으로 조립한다.
- 프론트 경계 검증은 과거 저장 데이터의 `new_expr`를 `own_remark`로 정규화한다. 현재 조각 타입과 렌더러에서는 별도 표현 분류·강조를 제거한다.
- Energy 안내는 경고 코드로 화면 표시 대상에서 제외한다. 음성 재생·피드백·성향 갱신의 다른 경고는 유지한다.
- DB 마이그레이션과 기존 데이터 변경은 없다.

## 확인

- 수정 전 실제 Gemini 호출에서 7개 필드와 `new_expr` 조각 생성을 확인했다.
- 수정 후 실제 Gemini 5건: A2/B1/B2/C1과 서로 다른 5축 분포에서 모두 유효한 응답을 조립했고, 별도 표현 조각이 없었다. 측정 중앙값은 900ms다. 제한된 표본의 모델 호출 시간이며 전체 음성 턴 지연과 다르다.
- 현재 계정으로 로컬 페이지에 다시 로그인한 뒤 360px 화면에서 실제 피드백 카드 2개의 캐릭터·턴 수·미리보기 제거와 피드백 상세의 턴 수 제거를 확인했다.
- 실제 GCP TTS 합성 음성을 녹음 입력으로 사용해 STT → Gemini → TTS → Supabase 저장 → UI 표시를 확인했다. 저장 재조회에서 turn ID·본문·조각이 일치했다. 교정만 라일락·굵기 600·밑줄이며 일반 문장은 기본색·굵기 400이었다.
- Energy 안내 표시 검사는 실제 종료 응답에 해당 안내 메타데이터만 주입해 수행했다. 종료 HTTP 200과 안내 미표시를 확인했다. 경계 검사에서는 다른 경고와 함께 와도 해당 안내만 숨기는지 확인한다.
- 최신 `main`의 ‘오늘의 표현’을 합친 코드에서 관련 Python 검사 305개와 정적 검사, 프론트 응답·Energy·오류·캐시·경로 검사 및 production 빌드를 통과했다. 기존 이미지 최적화 권고가 있다.

### 검증 범위와 남은 데이터

- 로컬 Python은 3.14이며 배포 런타임 3.11과 다르다. CI는 저장소 설정의 Python 3.11로 실행한다.
- 로컬 전체 연결 검증은 기존 rule 분석기를 사용했고 음성 Energy·주기적 작업은 비활성화했다. 운영 5축 모델과 음성 Energy 계산 자체를 재검증한 결과는 아니다.
- 검증용 대화 2개는 종료 상태로 남겼다. 하나는 선발화만 있고, 다른 하나는 음성 1턴을 저장했다. 일일 잔여량은 16회에서 15회로 바뀌었다. 계정 데이터 삭제는 실행하지 않았다.
- 근거는 로컬 `output/remove-new-expression-20261029/`의 응답 기록·모바일 캡처다. 인증정보와 음성 원문 파일은 기록하지 않았다.
