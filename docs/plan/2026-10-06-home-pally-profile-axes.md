# 홈 Pally 기준 통일과 홈 재진입 로딩

기준: 2026-10-06 KST, main `8c9be94` 위 `feat/home-pally-profile-axes`.
선행 문서: [프론트 오프너·피드백·기록 삭제 통합 검증](2026-10-06-frontend-opener-feedback-integration.md).

## 배경

opener 연동으로 "대화 시작하기"를 누르면 대화 row가 먼저 생겨, 한 마디도 안 한 완료 대화가 생길 수 있다. 홈은 가장 최근 완료 대화 1개의 `current_axes`로 Pally를 그렸고, 발화가 없는 대화의 `current_axes`는 초기값으로 내려와 홈 Pally가 최종 모습이 아니게 됐다. 마이페이지 태그와 다음 대화의 EMA 출발점은 정상이라 화면마다 기준이 달랐다.

## 결정

- 현재 Pally의 출처는 프로필 `current_axes` 하나다(민주 `28fb3f7`). 홈·마이페이지 태그·다음 대화 출발점이 같은 값을 쓴다. 대화 목록 항목의 `current_axes`는 "그 대화의 축"으로 의미를 유지한다.
- 첫 Pally 기준은 프론트 `DEFAULT_AXES`(50/30/20/10/15)다. 9월 22일 기본 태그 마이그레이션이 이 값을 기준으로 했고, 백엔드 `_INITIAL_AXES`(전부 50)만 어긋나 있었다. `_INITIAL_AXES`를 `DEFAULT_AXES`에 맞추고, 기본 태그와 어긋나면 실패하는 테스트를 추가했다.
- `_carried_over_axes`는 "발화가 있는 가장 최근에 **끝낸**(ended_at) 대화"의 마지막 5축을 준다. 생성 시각 기준이면 지난 대화를 이어 하고 끝냈을 때 마이페이지 태그(방금 끝낸 대화)와 홈 Pally가 서로 다른 대화를 가리킨다.
- 홈 재진입은 전체 화면 로더 대신 마지막으로 알던 상태를 바로 그리고 뒤에서 갱신한다. 진행 중인 대화가 있거나 `?conversation_id`가 있으면 기존대로 로더 후 복원한다. 갱신이 끝날 때까지 시작·마이크 버튼은 잠근다.

## 구현

- 캐시: `invalidate`는 값을 지우지 않고 만료만 표시한다. `peekStale`·`writeStale`·`evict` 추가. 로그아웃·탈퇴·기록 삭제는 `clearUser`로 완전 삭제한다. 요금제 변경 후 사용량·구독은 `evict`로 이전 값을 버린다.
- 홈: 프로필 `current_axes`로 Pally를 그린다. 값이 없으면(구 백엔드) 기본 모습을 쓴다. 세션 확인 결과 계정이 다르거나 로그아웃 상태면 그려둔 스냅샷을 버린다.
- 대화 종료 시 새 5축을, 발화 응답의 사용량을 stale 값으로 캐시에 반영해 홈 복귀 때 이전 값이 깜빡이지 않게 했다.
- 홈 시작 화면 문구를 "Pally's here to chat!"으로 변경했다.
- History 카드는 제목 줄 수만큼 높이가 늘어난다(한 줄은 기존 134px 유지).
- `check:home-snapshot` 추가(CI 포함). 백엔드는 `_INITIAL_AXES`, 정렬 기준 테스트를 추가·수정했다.

## 검증

대상: 기존 로그인 계정, Railway `web-production-8dee5.up.railway.app`(배포 시점의 백엔드), 로컬 localhost:3000 프론트. 도구의 viewport 에뮬레이션은 지원되지 않아 브라우저 기본 창 폭에서 확인했고, 실제 모바일 기기 검증은 아니다.

- 정적: `tsc --noEmit`, `npm run lint`, `npm run build`, `check:home-snapshot`·`check:query-cache`·`check:opener`·`check:feedback-sentence`·`check:mock-api`·`check:conversation-order`·`check-billing-account-binding` 통과. 백엔드 CI 명령 그대로 266개 통과, `ruff --select E9,F63,F7,F82`·`compileall` 통과.
- 배포된 백엔드의 프로필에 `current_axes`가 있음을 확인했다.
- 홈 재진입(History → 홈): 76프레임 중 로더 0프레임, 홈은 13ms에 그려졌고 사용량 표시는 바뀌지 않았다. 새로고침 첫 측정에서는 로더가 6프레임 보였다(둘째 측정은 로더가 뜨기 전에 샘플링이 시작돼 결론 없음).
- 홈 Pally의 5축이 콜드 로드와 재진입 첫 프레임 모두 서버 프로필 값과 같았다.
- opener만 듣고 종료한 대화(목록 API는 이 대화의 축을 전부 50으로 반환): 홈 Pally가 종료·재진입·새로고침 모두에서 유지됐고 서버 프로필·마이페이지 태그도 그대로였다.
- 발화가 있는 대화 종료 3회: 종료 시 새 5축으로 `revealAxes`가 호출되고, History 왕복 중 5축이 한 번도 바뀌지 않았으며 서버 프로필·마이페이지 태그와 일치했다. 종료 직후 값을 React fiber로 읽은 한 번의 측정은 이중 버퍼 때문에 이전 값이 읽혔고(앱 버그 아님), 계측 로그로 정상 호출을 확인했다.
- History 제목: 1줄 134px, 2줄 152px, 4줄 200px, 6줄 248px. 띄어쓰기 없는 긴 단어도 줄바꿈되고 가로 넘침·버튼 이탈이 없었다(4·6줄은 화면에서 제목 텍스트를 임시로 바꿔 측정).

테스트 레코드(모두 completed로 남김, 기존 기록은 삭제하지 않음):

## 남은 확인

- 백엔드 `_INITIAL_AXES`·`ended_at` 정렬은 배포 전이라 실서비스에서 확인하지 못했다. `sessions(ended_at)` 정렬은 사용자 토큰으로 Supabase REST에 보내 파싱은 통과했으나(권한 오류로 종료) 서버 전용 테이블이라 실제 정렬 결과는 못 봤다. 배포 후 확인: (1) 신규 계정 또는 기록 삭제 직후 홈 Pally와 기본 태그가 일치하는지, (2) 지난 대화를 이어 하고 종료한 뒤 홈·마이페이지가 같은 대화를 가리키는지.
- 계정 전환 시 이전 사용자의 Pally가 안 보이는지는 두 번째 계정이 없어 코드와 `check:home-snapshot`으로만 확인했다.
- 종료 직후 캐시 갱신(stale 패치)은 브라우저에서 서버 갱신과 분리해 확인하지 못했고, 앱 안에서 직접 말한 뒤의 사용량 갱신 경로도 합성 음성을 API로 보내 브라우저로 보지 못했다.
- 실제 마이크 입력과 실제 모바일 기기, 360px 폭 에뮬레이션은 미검증이다.
- 대화 중 피드백 안내가 Pally 답변마다 반복되고 짧은 말풍선 영역이 118px 줄어든 점은 이번 범위에 넣지 않았다.
